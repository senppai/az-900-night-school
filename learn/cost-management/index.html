💰Azure cost management

What makes an Azure bill go up, how the pricing calculator estimates before you deploy, what Cost Management does after you spend, and why tags are labels — not locks.

💰Azure is a consumption service. You pay for what you use, where you use it, and how you committed to pay. This lesson is the grocery list, the estimate before you shop, the receipt after, and the sticky notes that say which department bought the milk.

Three clocks matter. Before you deploy, you estimate. After resources are running, you watch real spend. Across both, you label resources so finance can see who owns which line on the bill. Mix those clocks up and the exam will catch you.

1. Factors that affect costs

The same VM size is not the same price everywhere. Region matters. Resource type and SKU matter (a tiny B-series VM is not an M-series monster). Usage meters matter: hours running, storage gigabytes, transactions, and especially bandwidth. Inbound data to Azure is often free or cheap; outbound data leaving Azure is where bills surprise people. How you buy matters too: pay-as-you-go, reservations or savings plans (commit for 1 or 3 years, lower rate), Spot VMs (spare capacity, can be evicted), and Azure Hybrid Benefit (reuse eligible Windows Server or SQL licenses).

  • ▹Resource type and SKU — what you run, and how big it is
  • ▹Region — prices differ by geography
  • ▹Meters / usage — time, storage, operations
  • ▹Bandwidth (egress) — data leaving Azure
  • ▹Purchase model — pay-as-you-go, reservations, Spot, Hybrid Benefit
  • ▹Redundancy and extras — geo-replication, support plans, marketplace images

Exam trap

“We turned the VM off in the portal” still leaves disks, public IPs, and some other resources billing. Stopped (deallocated) is the state that stops VM compute charges. Also: a reservation is a billing discount, not a different kind of virtual machine.

2. Pricing Calculator

The Azure Pricing Calculator is a public website. You add the services you are thinking about, pick region and size, and it estimates a monthly cost before anything exists in your subscription. It is a planning tool. It does not see your real bill.

Pricing Calculator

Before you deploy

  • • Estimate proposed Azure resources
  • • No subscription required to play with it
  • • Great for “what would this architecture cost?”

Azure Migrate business case

On-prem vs Azure

  • • Replaces the retired standalone TCO Calculator
  • • Compares running servers on-prem vs in Azure
  • • Migration business case — not your live bill

Cost Management

After you spend

  • • Real usage and invoices
  • • Budgets, alerts, cost analysis
  • • Lives in the Azure portal against your account

Think

Pricing Calculator = shopping-cart estimate. Azure Migrate business case = “should we leave the old datacenter?” (older material calls this the TCO Calculator). Cost Management = looking at the receipt.

3. Cost Management capabilities

Microsoft Cost Management (often shown with Billing) is where you analyze actual spend. You can break costs by subscription, resource group, service, and tag. You can set a budget — for example, $5,000 this month on the marketing subscription — and alerts when you hit 80% or 100%. You can export data to a storage account for finance tools. It can show recommendations, but it does not deploy architecture for you and it does not lock a resource from deletion.

What Cost Management is for

  • ★Cost analysis of real Azure spend
  • ★Budgets and alerting when you approach a limit
  • ★Breakdowns by tag, resource, and service
  • ★Helping people take action — it does not replace RBAC or Policy

4. The purpose of tags

A tag is a name/value label you attach to a resource or resource group: Department = Finance, Project = Apollo, Environment = Prod. Azure can roll costs up by those labels so each team sees its slice of the bill. Tags are also handy for operations (“who owns this?”). They are metadata. They do not change how the resource runs.

Exam trap

Tags are not resource locks. A tag will not stop someone from deleting a VM. A lock will. Tags are also not Policy — though Policy can require that a tag exists. If the question is “group costs by department,” the answer is tags. If it is “prevent deletion,” the answer is a lock.

Think

Tags = sticky notes. Useful, cheap, easy to ignore if nobody applies them. Locks = padlocks. Different object, different job.

5. Cost optimization options

The official module now ends with ways to pay less for the same work. Azure Reservations: commit to a specific resource (for example a VM size in a region) for 1 or 3 years and get a large discount — best for steady, predictable workloads. Azure savings plan for compute: commit to a fixed hourly spend on compute for 1 or 3 years; the discount applies across VM sizes, regions, and some PaaS compute, so it is more flexible than a reservation. Spot pricing: use spare Azure capacity at a deep discount, but Azure can evict the VM when it needs the capacity back — only for interruptible jobs. Azure Hybrid Benefit: reuse Windows Server and SQL Server licenses you already own (with Software Assurance) to cut the price. And the everyday habits: right-size VMs, shut down or deallocate what is idle, and act on Azure Advisor's cost recommendations.

Pick the discount that fits the workload

Exam trap

Reservation = locked to a resource type and region. Savings plan = locked to a spend amount, flexible on what you run. Spot is never the answer for production that must stay up.

One sentence to remember

Azure cost depends on what you run, where you run it, how much you use (especially egress), and how you pay; the Pricing Calculator estimates before you deploy, Cost Management watches the real bill, and tags label resources for that bill without protecting them from deletion.

Exam-style scene · Exam-style scene

A finance partner wants each Azure resource labeled so next quarter's invoice can be split by department. They also ask whether those labels will stop engineers from deleting production databases.

Pick: Use tags for the split; they will not prevent deletion. Add resource locks if you need delete protection.

Tags are metadata for grouping and reporting. Locks are the padlock. The exam loves offering tags as a fake answer to a deletion question.
