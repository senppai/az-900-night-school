Lesson 05 · Cloud concepts

🍽️IaaS, PaaS, and SaaS

Infrastructure, platform, and software as a service — who manages what, when to pick each, and the classic VM vs App Service vs Microsoft 365 comparison.

18 min read

You will understand

  • ✦What IaaS, PaaS, and SaaS each give you
  • ✦Who patches what in each model
  • ✦When a VM, App Service, or Microsoft 365 is the right picture
  • ✦How to read exam scenarios without mixing the three

Why this shows up on AZ-900

If you must manage the operating system, it is IaaS. If you deploy code and Microsoft runs the OS, it is PaaS. If you just use the app in a browser, it is SaaS. Watch for Azure Virtual Machines vs Azure App Service vs Microsoft 365 / Outlook.

Official Microsoft Learn module

Describe cloud service types ↗

Units covered in this lesson:

  • Describe Infrastructure as a Service
  • Describe Platform as a Service
  • Describe Software as a Service

🍕IaaS, PaaS, and SaaS are not three brands of Azure. They are three levels of "how much dinner Microsoft cooks." IaaS rents you a kitchen. PaaS rents you a kitchen that is already set up — you bring the recipe (your code). SaaS is a restaurant: you sit down and eat. The exam is almost always asking which level of control — and which level of chores — the story describes.

You already saw this ladder on the shared responsibility lesson. Here we stay on the services themselves: what you buy, what you still do, and the three examples Microsoft loves — virtual machines, App Service, and Microsoft 365 (Outlook, Teams, Word in the browser).

Think

IaaS = rent the VM. PaaS = rent the platform, deploy your app. SaaS = use the finished software.

IaaS — infrastructure as a service

IaaS is the closest cloud cousin of "a server in the basement." Microsoft provides the virtual hardware: VMs, disks, virtual networks, load balancers. You choose the OS image, patch it, install IIS or nginx, configure backups, and own the guest. You gained speed (a VM in minutes) and skipped buying a rack. You did not skip being a sysadmin for that VM.

  • ▹Azure Virtual Machines is the textbook IaaS example
  • ▹Also in the IaaS neighborhood: Virtual Network, many load-balancer setups, when you own the OS
  • ▹Use it to lift-and-shift an existing server, run custom software that needs the full OS, or lift a network appliance
  • ▹Most control, most of the chores

PaaS — platform as a service

PaaS is the sweet spot for a lot of new apps. Microsoft provides the OS, runtime, and platform features (deployment slots, scaling, patches). You provide the application and its configuration. Azure App Service (web apps) is the classic. Azure SQL Database is PaaS for databases: you get a database, not a SQL VM you have to patch. Azure Functions (serverless) sits at the PaaS end of the spectrum — even less server to see.

Think

PaaS = you bring the app. Microsoft brings the OS and the plumbing.

SaaS — software as a service

SaaS is finished software delivered over the internet. You configure it and use it. You do not deploy code to it (except maybe extensions). Microsoft 365 — Outlook, Exchange Online, Teams, Word, SharePoint — is the AZ-900 example you should be able to pick in your sleep. Dynamics 365 is another. You are a tenant of the application. Microsoft runs the app, the OS, and the hardware.

The comparison the exam will actually give you

Azure Virtual Machines

IaaS

  • • You pick and patch the OS
  • • Lift-and-shift, custom software, full control
  • • You are still the sysadmin of that guest

Azure App Service

PaaS

  • • You deploy a web app / API
  • • Microsoft manages OS and web platform
  • • "Host a website without managing servers"

Microsoft 365 / Outlook

SaaS

  • • You use email, docs, Teams
  • • Microsoft runs the application
  • • "Give people email without installing Exchange"

Pick the service type from the story

Migrate a server as-is; need the OS; install extra agentsIaaSAzure Virtual Machines

Users just need the app; we will not build itSaaSMicrosoft 365, Outlook, Teams, Dynamics 365

AZ-900 exam points

  • ★IaaS: infrastructure, you manage the OS
  • ★PaaS: platform, you manage your app and data
  • ★SaaS: software, you manage data and access
  • ★VM vs App Service vs Microsoft 365 is the triangle to memorize

Exam trap

Azure SQL Database is PaaS. A SQL Server you install on a VM is IaaS. Same database engine family, different chore list. If you have to patch Windows or SQL Server yourself, you are in IaaS. If Azure SQL patches for you, you are in PaaS.

Exam trap

The Azure portal is how you manage Azure. It is not "SaaS vs IaaS" for your workload. Do not pick SaaS just because someone used a browser. Outlook is SaaS. Creating a VM in the portal is still IaaS.

  1. 1. Hear "virtual machine" or "install on Windows Server"

    IaaS.

  2. 2. Hear "web app," "App Service," or "don't manage the OS"

    PaaS.

  3. 3. Hear "Outlook," "Microsoft 365," "Teams," or "just use the software"

    SaaS.

  4. 4. Hear "serverless" / Azure Functions

    Treat it as PaaS (the extreme end): you bring code, no servers to see.

One sentence to remember

IaaS rents you the VM and you run the OS, PaaS rents you a platform so you only run your app, and SaaS rents you the app itself — VMs, App Service, and Microsoft 365 are the three pictures to keep in your pocket.

Exam-style scene · Exam-style scene

Adventure Works wants employees to have email, calendars, and Teams meetings. They do not want to install or patch Exchange Server. They also have a custom public website they will write in .NET and do not want to manage Windows for that site. Finally, a legacy payroll package must run on a specific Windows Server version.

Pick: Email/Teams = SaaS (Microsoft 365). Website = PaaS (App Service). Payroll = IaaS (Azure VM).

One company, three service types. The exam loves stacking them in a single paragraph so you match each workload instead of picking one answer for the whole company.
