📡Monitoring Azure: Advisor, Service Health, and Monitor

Azure Advisor for recommendations, Azure Service Health for “is my stuff on fire,” and Azure Monitor — Log Analytics, alerts, and Application Insights — for telemetry.

18 min read

You will understand

  • ✦The five recommendation categories in Azure Advisor
  • ✦Service Health vs Resource Health vs the public Azure Status page
  • ✦What Azure Monitor is, including Log Analytics and alerts
  • ✦When Application Insights is the right name on a question

Why this shows up on AZ-900

Advisor suggests. Service Health is personalized to your subscriptions (Status is the public page). Monitor collects metrics and logs; Log Analytics queries them; alerts notify; Application Insights watches your app.

Describe monitoring tools in Azure ↗

Units covered in this lesson:

  • Describe the purpose of Azure Advisor
  • Describe Azure Service Health
  • Describe Azure Monitor

📡Azure can recommend better setups, tell you when Microsoft is having a bad day that actually hits you, and collect the numbers and logs your apps produce. Those are three different products. The exam will offer all three as answers to the same story. We will give each one a job description.

A hospital analogy helps. Azure Advisor is the consultant who walks the wards and says “this bed could be cheaper, this door should be locked.” Azure Service Health is the hospital operator telling you which of your rooms are affected by a water outage. Azure Monitor is the banks of screens: heart rate, temperature, alarms, and a specialist who only watches one patient (your application).

1. Azure Advisor

Azure Advisor looks at your resources and produces personalized recommendations. It does not deploy them for you unless you choose to act. For AZ-900, memorize the five categories: Cost, Security, Reliability, Operational excellence, and Performance. (You may also see Sustainability in the product; the exam still hangs on those five.) Advisor is not an outage dashboard and it is not a log query tool.

  • ▹Cost — unused public IPs, idle VMs, reservations you could buy
  • ▹Security — follow-up on hardening (Defender for Cloud often feeds this story)
  • ▹Reliability — make things survive failure (zones, backups, redundancy)
  • ▹Operational excellence — follow good practices, subscriptions, notifications
  • ▹Performance — SKUs, caching, throughput that is too small

Think

Advisor = “here is how to run Azure better.” If the scenario is an ongoing Microsoft outage, Advisor is the wrong answer.

2. Azure Service Health

Azure Service Health is personalized. It knows your subscriptions and tells you about issues that affect you: service problems, planned maintenance, health advisories, and security advisories. You can set up alerts so someone is paged when Microsoft posts an incident on a service you actually use. Resource Health is the sibling view for one resource: “is this particular VM healthy right now, and was it Microsoft's fault?” The public Azure Status page is different — a global billboard for everyone, not tailored to your account.

Azure Status

Public billboard

  • • status.azure.com (and similar public views)
  • • Worldwide picture of Azure
  • • Not customized to your subscriptions

Azure Service Health

Your subscriptions

  • • Service issues that hit you
  • • Planned maintenance
  • • Health and security advisories
  • • You can alert on it

Resource Health

This one resource

  • • Is this VM / SQL / app healthy?
  • • Helps tell platform vs your configuration
  • • Zooms in from Service Health

Exam trap

Azure Status is not Service Health. Status = everyone. Service Health = you. If the question says “notify us when an Azure outage affects our subscription,” the answer is Service Health (with alerts), not the public Status page and not Advisor.

3. Azure Monitor

Azure Monitor is the umbrella for collecting, analyzing, and acting on telemetry. Metrics are numerical measurements over time (CPU %, request count). Logs are records of events. Monitor sits in the middle: data comes in from Azure resources, from guests, from apps; you chart it, query it, alert on it, and optionally send it out.

4. Log Analytics

Log Analytics is the workspace where logs live and where you query them (the language is Kusto Query Language, or KQL — you do not need to write KQL for AZ-900). Think of it as the searchable archive: “show me failed sign-ins,” “show me disk errors on these VMs.” The workspace is the container. Azure Monitor uses it. Many other services send data into it.

5. Azure Monitor alerts

Alerts are the “tap someone on the shoulder” piece. A condition fires — CPU over 90% for 10 minutes, a log query returns failures, a Service Health incident starts — and an action group emails, SMS, or calls a webhook. Alerts are not recommendations (that is Advisor) and they are not the public Status page. They are rules you define, watching your data.

6. Application Insights

Application Insights is Azure Monitor's Application Performance Management (APM) feature. You point it at your web app or service and it tracks request rates, response times, failures, dependencies, and live metrics. If the question is about an application — “why is our website slow, where are the exceptions” — Application Insights is the named answer. If the question is about an Azure region outage, it is Service Health. If it is about unused disks, it is Advisor.

AZ-900 exam points

  • ★Advisor: Cost, Security, Reliability, Operational excellence, Performance
  • ★Service Health: your issues, maintenance, advisories — not the public Status page
  • ★Resource Health: this one resource
  • ★Azure Monitor: metrics + logs hub
  • ★Log Analytics: query logs in a workspace
  • ★Alerts: notify when a condition is true
  • ★Application Insights: watch the application's health and performance

One sentence to remember

Advisor recommends how to run Azure better, Service Health tells you when Microsoft's issues (or maintenance) hit your subscriptions — unlike the public Status page — and Azure Monitor is the telemetry hub with Log Analytics to query, alerts to notify, and Application Insights to watch your app.

Exam-style scene · Exam-style scene

An operations lead wants two things: a weekly list of unused public IP addresses to delete, and a text message if Azure reports an outage that affects this company's subscriptions.

Pick: Azure Advisor for the unused IPs (Cost); Azure Service Health alerts for the outage texts.

Advisor finds waste. Service Health is personalized incident information you can alert on. Application Insights would be for the app's own exceptions. The public Status page would not know which subscriptions are yours.
