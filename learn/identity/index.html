🪪Azure identity: Microsoft Entra ID

Microsoft Entra ID, Entra Domain Services, SSO, MFA, passwordless, external identities, and Conditional Access — who you are before anyone asks what you can do.

18 min read

You will understand

  • ✦What Microsoft Entra ID is — and why it used to be called Azure AD
  • ✦When Microsoft Entra Domain Services shows up instead of Entra ID
  • ✦SSO, MFA, and passwordless in plain language
  • ✦External identities and Conditional Access as exam-style if/then rules

Why this shows up on AZ-900

Microsoft renamed Azure AD to Microsoft Entra ID. If a question still says Azure AD, it means Entra ID. Do not mix Entra ID (cloud directory) with Entra Domain Services (managed legacy domain).

🪪Before Azure lets anyone create a virtual machine or open a storage account, it wants to know who they are. That is identity. This lesson is the guest list, the badges, and the extra checks at the door — not the job titles that decide what you can do once you are inside.

Keep one pair of words straight from the first minute. Authentication is proving who you are (the badge). Authorization is what you are allowed to do (the job title). This lesson is mostly authentication. Azure role-based access control — the authorization side — gets its own lesson next.

1. Microsoft Entra ID (formerly Azure AD)

Microsoft Entra ID is Azure's cloud identity and access management directory. It stores users, groups, and applications. When someone signs in to the Azure portal, Microsoft 365, or thousands of other apps, Entra ID is usually the service checking the badge. It used to be named Azure Active Directory, or Azure AD. Same product, new name. The exam may still say Azure AD. Answer as if it said Microsoft Entra ID.

Think

Microsoft Entra ID = the cloud guest list. Users, groups, and apps live here. It is not a virtual machine and it is not a firewall.

Exam trap

Never treat "Azure AD" as a different product. Azure AD was renamed to Microsoft Entra ID. If a question says Azure AD, it means Entra ID.

2. Microsoft Entra Domain Services

Some older apps still speak the language of on-premises Active Directory Domain Services: domain join, LDAP, Kerberos, NTLM, Group Policy. Microsoft Entra Domain Services is a Microsoft-managed domain for those apps. You do not stand up your own domain controllers. Microsoft runs them. Lift-and-shift a legacy app onto Azure VMs, and it can still behave as if it were on a classic domain.

Microsoft Entra ID

Cloud directory

  • • Users, groups, and modern apps
  • • Sign-in with protocols such as OAuth, OpenID Connect, and SAML
  • • SSO, MFA, Conditional Access
  • • The default identity service for Azure and Microsoft 365

Microsoft Entra Domain Services

Managed legacy domain

  • • LDAP, Kerberos, NTLM, Group Policy
  • • Domain-join Azure VMs that need classic AD
  • • Microsoft manages the domain controllers
  • • For apps that cannot speak modern cloud identity yet

Exam trap

Entra Domain Services is not “Entra ID with extra features.” It is a managed traditional domain for legacy apps. If the scenario says LDAP, Kerberos, or domain-join without managing DCs, think Domain Services — not Entra ID alone.

3. Authentication: SSO, MFA, and passwordless

Single sign-on (SSO) means you sign in once and then open many apps without typing the password again. One badge, many doors. Multifactor authentication (MFA) means Azure wants a second proof — something you know (password), something you have (phone or hardware key), or something you are (fingerprint or face). Passwordless goes further: you sign in with Windows Hello, a FIDO2 security key, or the Microsoft Authenticator app, without a password at all.

Think

SSO = convenience across apps. MFA = extra proof. Passwordless = proof without a password. They can work together: SSO that still demands MFA when the sign-in looks risky.

4. External identities

Not everyone who signs in works at your company. External identities let people outside your organization use their own credentials with your apps. AZ-900 usually paints two pictures. Business-to-business (B2B) is a guest user: a partner or contractor you invite into your directory. Business-to-consumer (B2C / customer identity) is people signing up for your public app — shoppers, patients, citizens — not employees.

5. Microsoft Entra Conditional Access

Conditional Access is an if/then policy engine on top of Entra ID. IF a sign-in looks a certain way, THEN require extra proof or block it. Signals include the user, the app, the location, the device, and the risk of the sign-in. It is not a network firewall. It is identity making a decision at sign-in time.

AZ-900 exam points

  • ★Microsoft Entra ID is the cloud identity directory (formerly Azure AD)
  • ★Microsoft Entra Domain Services = managed AD DS for legacy apps
  • ★SSO = one sign-in, many apps
  • ★MFA = more than one proof of identity
  • ★Passwordless = Windows Hello, FIDO2, Authenticator — no password
  • ★External identities = guests and customers, not only employees
  • ★Conditional Access = if this sign-in, then this extra requirement

One sentence to remember

Microsoft Entra ID (formerly Azure AD) is the cloud directory that authenticates people; Domain Services covers legacy domain apps; SSO, MFA, and passwordless are how you prove it is you; external identities bring guests and customers in; Conditional Access adds if/then rules on top of the sign-in.

Exam-style scene · Exam-style scene

A company moves an old line-of-business app to Azure virtual machines. The app must domain-join and use Kerberos. The team does not want to manage domain controllers.

Pick: Microsoft Entra Domain Services

That is the managed traditional domain. Entra ID handles modern cloud sign-in; it does not replace LDAP/Kerberos for that legacy app.
