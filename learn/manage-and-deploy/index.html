Lesson 15 · Management & governance

🧰Managing and deploying Azure resources

Portal, Cloud Shell, CLI, PowerShell, Arc, ARM, ARM templates, and Bicep — and how they all fit together.

18 min read

You will understand

  • ✦The difference between Cloud Shell, CLI, and PowerShell
  • ✦What ARM actually is (hint: not a command-line tool)
  • ✦Why Bicep exists if ARM templates already exist
  • ✦What Azure Arc is — and what it is not

Why this shows up on AZ-900

Microsoft loves mixing these names. If you can tell a management tool from a deployment language from Azure's control plane, you will pick up easy points.

Official Microsoft Learn module

Describe features and tools for managing and deploying Azure resources ↗

Units covered in this lesson:

  • Describe tools for interacting with Azure
  • Describe the purpose of Azure Arc
  • Describe Azure Resource Manager and Azure ARM templates

☁️This topic is very important for AZ-900, because Microsoft gives you several ways to manage and deploy Azure resources, and some of the names can be confusing. The easiest way is to separate them into management tools and deployment / infrastructure tools.

First, understand the big picture. You have Azure resources like virtual machines, storage accounts, virtual networks, databases, and App Services. You need ways to create, configure, manage, and deploy them. Microsoft gives you several tools for doing that.

1. Azure Cloud Shell

Azure Cloud Shell is a command-line environment inside your browser. Instead of installing tools on your computer, you can open Cloud Shell directly from the Azure portal. Inside it, you can use Azure CLI or Azure PowerShell.

Think

Cloud Shell = a terminal in your browser.

AZ-900 exam point

  • ★Accessible through a browser — no local install required
  • ★No need to configure Azure tools on your laptop
  • ★Supports Azure CLI
  • ★Supports Azure PowerShell

Exam trap

Cloud Shell is not a new language. It is the place you type. CLI and PowerShell are the languages you type in.

2. Azure CLI

CLI means Command-Line Interface. Azure CLI lets you manage Azure resources by typing commands. It is command-based, cross-platform, and available on Windows, Linux, and macOS.

Think

Azure CLI = commands starting with az. az vm create. az group create. az storage account create.

Exam memory

  • ★CLI → az commands

3. Azure PowerShell

Azure PowerShell is another way to manage Azure resources, using PowerShell commands. Both CLI and PowerShell can accomplish similar things. The difference is primarily the command-line environment and the syntax.

Azure CLI

az …

  • • Commands start with az
  • • Feels like a typical Linux/macOS CLI
  • • Great if you already like bash-style commands

Azure PowerShell

Az cmdlets

  • • Commands look like New-AzResourceGroup
  • • Verb-Noun style (New, Get, Set, Remove)
  • • Great if you already live in PowerShell and automation

Think

Azure CLI → az. Azure PowerShell → Az PowerShell commands.

4. Azure Arc

This one is different. Azure Arc allows you to manage resources that are outside Azure using Azure management capabilities. Your company might have servers in Azure, servers in its own datacenter, and servers running in another cloud. Azure Arc can help you manage those resources through Azure.

Exam trap

Azure Arc does not mean "move everything into Azure." It extends Azure management to resources that stay where they are.

Think

Arc = Azure reaches outside Azure. Manage hybrid and multicloud resources from Azure.

5. ARM — Azure Resource Manager

ARM is the management layer of Azure. When you create or manage Azure resources, ARM handles creating, updating, and deleting them. It also handles access control, resource organization, tags, locks, and policies.

So when you use the Azure portal to create a VM, ARM is involved behind the scenes. When you use Azure CLI (az vm create), ARM is also involved.

Think

ARM is not just another command-line tool. It is the management layer that receives requests and manages Azure resources.

6. ARM templates

Now we get into Infrastructure as Code (IaC). Suppose you need to create 5 VMs, 2 storage accounts, 1 virtual network, and 3 subnets. You could click through the portal. That is slow and easy to mess up. Instead, you describe your infrastructure in a template. That is an ARM template: a JSON file that describes the Azure resources you want to deploy.

Why ARM templates show up on the exam

  • ★Infrastructure as Code — the setup is written down, not clicked
  • ★Repeatable deployments
  • ★Consistent environments (dev looks like prod)
  • ★Automation and reuse

7. Bicep

This is probably the easiest one once you know ARM templates. Bicep is a language for deploying Azure resources. It is designed to be easier to write than ARM JSON templates. ARM templates use JSON and can become huge and hard to read. Bicep uses a much cleaner syntax. Under the hood, Bicep still deploys through Azure Resource Manager.

Think

Bicep is a simpler, cleaner way to define Azure infrastructure while still using ARM for deployment.

The relationships that actually matter

This is the part to lock in for the exam. Management tools talk to ARM. ARM talks to resources. Infrastructure as Code also talks to ARM. Arc is the special case that lets ARM-style management reach outside Azure.

    "I want a terminal without installing tools."

  2. 2. Azure CLI

    "I want to type az commands."

  3. 3. Azure PowerShell

    "I want to use PowerShell commands."

  4. 4. Azure Arc

    "I want Azure management for resources outside Azure."

  5. 5. ARM

    "Azure's resource management layer."

  6. 6. ARM template

    "I want to define infrastructure using JSON."

  7. 7. Bicep

    "I want Infrastructure as Code with a simpler Azure-specific language."

One sentence to remember

Cloud Shell is where you work, CLI and PowerShell are how you give commands, ARM manages the resources, Bicep and ARM templates define what you want deployed, and Azure Arc lets Azure manage resources outside Azure.

Exam-style scene · Exam-style scene

A company has servers in its own datacenter and wants to manage them with Azure Policy and Azure tags, without moving those servers into Azure.

Pick: Azure Arc

Arc extends Azure management to machines that stay outside Azure. It is not a lift-and-shift tool.
