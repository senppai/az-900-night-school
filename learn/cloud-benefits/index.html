Lesson 04 · Cloud concepts

📈Benefits of using cloud services

High availability, scale-up vs scale-out, elasticity, reliability, cost and performance predictability, security, governance, and manageability — the reasons companies actually move.

16 min read

You will understand

  • ✦High availability vs reliability, in human language
  • ✦Vertical scaling, horizontal scaling, and elasticity
  • ✦Performance predictability vs cost predictability
  • ✦What security, governance, and manageability mean in the cloud
  • ✦Why sustainability is now on the list of cloud benefits

Why this shows up on AZ-900

Microsoft will describe a symptom (Black Friday traffic, a failed disk, a surprise bill, a patch Tuesday) and want the benefit by name. Vertical vs horizontal scaling is the mix-up they never get tired of.

Describe the benefits of using cloud services ↗

Units covered in this lesson:

  • Describe the benefits of security and governance in the cloud

🎯Companies do not move to Azure because "cloud" sounds modern. They move because a well-designed cloud app can stay up, grow when it is busy, shrink when it is quiet, fail over when hardware dies, and be managed without a plane ticket to a datacenter. This lesson is the vocabulary for those wins.

AZ-900 groups the benefits into four clusters: high availability and scalability; reliability and predictability; security and governance; manageability. Learn the clusters, then learn the words inside them so a scenario maps to one term, not a vague "it's better."

Think

Every benefit answers a pain: downtime, sudden load, surprise bills, patch chaos, or "who is allowed to do what."

High availability

Availability is the percentage of time a system does what users need. High availability (HA) means you designed it so a single failure does not take the whole thing down — extra instances, extra datacenters, load balancers, SLAs. Azure regions and availability zones exist so you can spread risk. An SLA like 99.99% is a contract about that design, not a magic spell.

Scalability: up vs out

Scalability is the ability to increase (or decrease) capacity when load changes. There are two directions, and the exam will use both names.

Vertical scaling

Scale up / scale down

  • • Same machine, more (or less) CPU, RAM, or disk
  • • Like replacing a laptop with a workstation
  • • Simple, but you eventually hit a ceiling
  • • Often involves a resize (and sometimes a reboot)

Horizontal scaling

Scale out / scale in

  • • More machines (or fewer), same role
  • • Like opening more checkout lanes
  • • The cloud-native way to handle huge load
  • • Needs a load balancer and an app that can run in many copies

Elasticity is scalability with an automatic spring. The system adds capacity when load rises and removes it when load falls, without a human opening a ticket. Black Friday is the story: scale out at 6 p.m., scale in at 2 a.m., stop paying for idle VMs. Scalability says you can grow. Elasticity says you grow and shrink by itself.

Think

Scale up = bigger box. Scale out = more boxes. Elasticity = the boxes appear and vanish on their own.

Exam trap

High availability is not the same as scalability. HA is "still up when something breaks." Scale is "handles more work." A single huge VM can be scalable vertically and still be a terrible HA story — that one VM is a single point of failure.

Reliability and predictability

Reliability is the system's ability to recover from failures and keep providing a consistent service — resiliency plus availability. Disaster recovery is the big-failure cousin: restore within an acceptable time (RTO) with an acceptable amount of data loss (RPO). The cloud helps because you can copy workloads to another region without buying a second building first.

Predictability has two flavors on AZ-900, and they are not interchangeable. Performance predictability means the app behaves consistently — you can size, test, and autoscale so users do not see random slowness. Cost predictability means you can forecast the bill — budgets, reservations, alerts — instead of discovering a surprise invoice. Same word, two exam answers.

Security and governance

Security in the cloud is not "Microsoft already did it" — you saw that in shared responsibility. The benefit is that you inherit a huge physical security program, plus a catalog of tools (identity, encryption, network controls, threat detection) that a 20-person company could not build alone. You still configure them.

Governance is how the organization stays in control: policies, standards, who can create what, which regions are allowed, tags for cost owners, audits. In Azure that later becomes Azure Policy, management groups, and RBAC. For this lesson, remember the idea: cloud makes it easier to apply the same rules everywhere, instead of hoping each office's server closet matches the spreadsheet.

AZ-900 exam points

  • ★HA: design so failures do not take you fully down
  • ★Vertical = bigger VM; horizontal = more VMs
  • ★Elasticity = automatic scale out and in
  • ★Reliability: recover and keep serving
  • ★Predictability: performance and/or cost
  • ★Security: platform capabilities + your configuration
  • ★Governance: enforce organizational rules at scale

Manageability in the cloud

Manageability is the unglamorous superpower. You manage resources through a browser (Azure portal), command lines (CLI, PowerShell, Cloud Shell), APIs, and templates — from anywhere, without a crash cart. Microsoft can patch the platform underneath PaaS and SaaS. You can automate the boring work. A related word you will see is agility: the ability to stand up a new environment in minutes when the business changes its mind.

Sustainability

The newest benefit on the Microsoft Learn list is sustainability. Large cloud datacenters run hardware much more efficiently than a server closet: servers are shared by many customers, so fewer machines sit idle; cooling and power are engineered at huge scale; and Microsoft buys renewable energy for its regions. When you scale in at night or delete what you do not use, you also stop drawing power for it. Microsoft gives customers carbon-emissions reporting so they can see the footprint of their cloud usage.

Think

Sustainability = do the same work with less energy and less idle hardware. Right-sizing and elasticity save money AND carbon.

Exam trap

Sustainability does not mean “Azure is carbon-free by default” or “you no longer have responsibilities.” You still choose sizes, regions, and when to turn things off. Unused resources still burn energy and money.

One sentence to remember

Cloud benefits are staying up (HA), growing the right way (scale up vs out, elasticity), recovering (reliability), avoiding surprises (predictable performance and cost), and running the place with security, governance, and remote manageability.

Exam-style scene · Exam-style scene

PixelForge's game store dies every launch day because one web server maxes out. They can tolerate many identical servers behind a load balancer, and they want extra servers to appear only during launches, then disappear.

Pick: Horizontal scaling plus elasticity (scale out automatically, then scale in)

A bigger single server would be vertical scaling and still one point of failure. The "appear and disappear" language is elasticity, not a one-time resize.
