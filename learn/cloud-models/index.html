Lesson 03 · Cloud concepts

🌐Public, private, and hybrid cloud

Public is Microsoft's shared Azure. Private is a cloud for one organization. Hybrid is both, connected on purpose. Multi-cloud exists, but AZ-900 grades you on the first three.

14 min read

You will understand

  • ✦What public, private, and hybrid actually mean
  • ✦When each model is the right answer
  • ✦Why "we have a firewall" is not a private cloud
  • ✦Where multi-cloud fits — and why it is extra context, not the exam core

Why this shows up on AZ-900

Read the constraint. Exclusive hardware or total control → private. Want Microsoft to own the fleet and a credit card to scale → public. Must keep some systems on-premises and still use Azure → hybrid.

Official Microsoft Learn module

Describe cloud computing ↗

Units covered in this lesson:

  • Define cloud models

🏠Cloud models answer one question: whose datacenter, and who else is in it? A hotel (public), a house you own (private), or living in your house and booking a hotel for guests when the in-laws visit (hybrid). Same idea as IaaS/PaaS/SaaS, different axis — this axis is deployment, not how much of the stack Microsoft manages.

AZ-900 wants three models: public, private, and hybrid. If a question mentions AWS plus Azure, that is multi-cloud — useful in real life, rarely the thing Microsoft is scoring. Start with the three, then we will park multi-cloud in a side note so it does not steal the answer.

Think

Public = shared hotel. Private = your house. Hybrid = house plus hotel on purpose.

Public cloud

Public cloud is what most people mean when they say "Azure." Microsoft owns the hardware, the buildings, and the global network. Anyone with a subscription can rent capacity. You share the physical fleet with other customers, but your resources are isolated logically. You get the catalog, the regions, and the ability to grow without buying a rack.

  • ▹No CapEx for datacenter hardware — you rent
  • ▹Fast to start, easy to scale globally
  • ▹You share physical infrastructure with other tenants (logical isolation, not a shared login)
  • ▹Least operational overhead for the building itself
  • ▹You still pick regions, configure services, and own your data

Private cloud

Private cloud looks and feels like cloud — on-demand VMs, self-service, metering — but the hardware is dedicated to one organization. It might sit in your building or in a facility only you use. You (or a partner who runs it just for you) own the exclusive use of those hosts. Azure Stack Hub is Microsoft's way to run Azure-like services in your datacenter. The exam care-about is exclusive use and control, not the product name.

Exam trap

A single VM in Azure is not a private cloud. "Private" is about dedicated infrastructure for one tenant, not about a private IP or a network security group. Those are just good public-cloud hygiene.

Hybrid cloud

Hybrid is the combination you meant to have: some workloads in a private environment (often on-premises), some in public Azure, connected so they work as one. Identity can sync. A database can stay in the basement while the website sits in Azure. Bursting — keep the baseline on-premises, overflow to Azure when a sale hits — is a classic hybrid story. Azure Arc, VPN Gateway, and ExpressRoute are the plumbing; you do not need those product deep-dives yet, just the idea that hybrid is connected on purpose.

Public

Azure, AWS, Google Cloud

  • • Provider owns the hardware
  • • Best for most startups and scale-out apps
  • • Lowest barrier to entry

Private

Your cloud, your hosts

  • • Dedicated hardware for one org
  • • Control and isolation that some regulations demand
  • • You still pay to run a datacenter

Hybrid

Both, connected

  • • Keep sensitive or awkward systems where they are
  • • Use Azure for scale, DR, or new apps
  • • Most large enterprises live here

Which model? Read the use case

  1. 1. Public

    "We want to start fast, pay as we go, and let Microsoft run the datacenter." Seasonal scale. Global reach. No appetite to own racks.

  2. 2. Private

    "This system must stay on dedicated hardware we control." Strict isolation, legacy licensing that forbids multi-tenant hosts, or a policy that data cannot leave our building.

  3. 3. Hybrid

    "Some systems stay in our datacenter, and we also want Azure." Migration in progress. Low-latency factory machines on-site plus a cloud app. Burst to the public cloud. Backup/DR into Azure.

AZ-900 exam points

  • ★Public: shared infrastructure, provider-owned, internet-delivered
  • ★Private: dedicated to one organization
  • ★Hybrid: public + private (or on-premises) together
  • ★Match the constraint in the story, not the company size

Multi-cloud is using more than one public cloud — Azure plus AWS, for example. Companies do it to avoid lock-in or because a team already built something on another provider. Azure Arc can help you manage those resources from Azure. For AZ-900, multi-cloud is extra vocabulary. If the options are public / private / hybrid, pick among those three. Multi-cloud is not a fourth official model on the skills list.

Exam trap

Hybrid is not "we might use Azure someday." Hybrid is an architecture that uses both. And hybrid is not the same as multi-cloud. Hybrid = on-premises/private plus public. Multi-cloud = two public clouds.

One sentence to remember

Public is Microsoft's shared Azure, private is a cloud dedicated to one organization, and hybrid is using both together on purpose — pick the model that matches the constraint, not the buzzword.

Exam-style scene · Exam-style scene

Tailwind Traders has a factory control system that must stay next to the machines, and a customer website they want to host in Azure and scale worldwide. They will connect the two with a private link.

Pick: Hybrid cloud

Two environments, both in active use, connected. The factory is not moving. The website is public cloud. That combination is hybrid, not private-only and not public-only.
