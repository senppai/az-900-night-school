Lesson 02 · Cloud concepts

🤝The shared responsibility model

Security in Azure is a split: Microsoft always owns the physical datacenter, you always own your data and access, and everything in between slides depending on IaaS, PaaS, or SaaS.

18 min read

You will understand

  • ✦Why "the cloud is secure" is the wrong sentence
  • ✦What Microsoft always owns vs what you always own
  • ✦How the split changes for IaaS, PaaS, and SaaS
  • ✦How to answer "who patches the OS?" style questions

Why this shows up on AZ-900

The exam will name a layer — physical hosts, operating system, application, data, identities — and ask who is responsible. If you can shift the line for IaaS vs PaaS vs SaaS, you will catch questions other people guess.

Official Microsoft Learn module

Describe cloud computing ↗

Units covered in this lesson:

  • Describe the shared responsibility model

🏢Moving to Azure does not mean Microsoft becomes your CISO. Think of an apartment building. The landlord owns the structure, the locks on the front door, the electricity, and the cameras in the lobby. You still lock your own flat, decide who gets a key, and choose whether you leave your laptop on the kitchen table. Shared responsibility is that split, written for cloud.

Microsoft's model is simple once you stop treating "security" as one blob. Some duties never leave Microsoft. Some duties never leave you. A middle band — operating systems, network controls, applications — moves toward Microsoft as you go from IaaS to PaaS to SaaS.

Think

Microsoft secures the cloud. You secure what you put in the cloud — especially data and access.

The layers that never move

Start with the extremes. If you remember only two lists, remember these. They show up on the exam as "always" questions.

Always Microsoft

The building

  • • Physical datacenters (buildings, cages, cameras, guards)
  • • Physical network (cables, core routers, backbone)
  • • Physical hosts (the actual servers under the hypervisor)

Always you (the customer)

Your flat

  • • Information and data — classification, encryption choices, backups you configure
  • • Accounts and identities — who can sign in, MFA, guest users
  • • Devices and endpoints that your people use
  • • Access management — keys, roles, sharing links

Exam trap

"Azure is responsible for security" is too vague to be the answer. Ask: security of what? The building? Yes. Your blob of payroll files and the intern's password? That is still you.

The line moves with the service type

IaaS, PaaS, and SaaS are taught in the next service-types lesson. For responsibility, you only need this: the more Microsoft provides as a finished service, the more Microsoft patches. You never get to dump data or identity onto them.

Think

IaaS = you patch the OS. PaaS = Microsoft patches the OS. SaaS = Microsoft runs the app. You always own the data and the keys to the door.

Physical datacenter vs data vs access vs OS vs application

Exam writers love to name one layer and wait. Walk the stack out loud. Physical datacenter: Microsoft, always — you cannot wander into an Azure region with a badge printer. Data: you, always — Microsoft will not decide your retention policy or whether that spreadsheet is confidential. Access: you — Entra ID roles, shared links, storage keys, SAS tokens. OS: you on a VM, Microsoft on App Service. Application: you if you wrote it, Microsoft if you are using theirs (Outlook, Teams, Dynamics).

AZ-900 exam points

  • ★Customer always: data, endpoints, accounts, access
  • ★Microsoft always: physical datacenter, physical network, physical hosts
  • ★On IaaS you still manage the guest OS
  • ★On PaaS Microsoft manages OS and runtime; you manage your app and data
  • ★On SaaS Microsoft manages the app; you still manage data and identities

  1. 1. If the question says "physical datacenter" or "host hardware"

    Microsoft. Every service type.

  2. 2. If it says "guest operating system" on a virtual machine

    You. That is IaaS. You patch Windows or Linux.

  3. 3. If it says "App Service" or "Azure SQL" and "patch the OS"

    Microsoft. That is PaaS.

  4. 4. If it says "who is responsible for the data in Microsoft 365?"

    You. SaaS does not donate your data to Microsoft's responsibility list.

  5. 5. If it says "who configures MFA and guest access?"

    You. Identities and access stay with the customer.

Exam trap

Do not confuse "Microsoft offers encryption features" with "Microsoft is responsible for your data." The platform gives you tools (encryption at rest, Key Vault, sensitivity labels). You choose to use them, you classify the data, you grant access. Tools are not a transfer of ownership.

One sentence to remember

Microsoft always owns the physical world under Azure, you always own your data and who can reach it, and the operating system and application slide toward Microsoft as you move from IaaS to PaaS to SaaS.

Exam-style scene · Exam-style scene

Adventure Works deploys a Linux virtual machine in Azure and later moves the same workload to Azure App Service. After the move, who is responsible for applying Linux security patches?

Pick: Microsoft, once it is App Service (PaaS). On the VM it was Adventure Works.

The guest OS is a customer job on IaaS. App Service is PaaS, so Microsoft maintains the OS and runtime. Adventure Works still owns the app code, the data, and access control either way.

Exam-style scene · Another exam-style scene

A manager says, "We use Microsoft 365, so Microsoft is responsible if an employee shares a confidential customer list with the wrong person." Is that right?

Pick: No. Sharing and access are customer responsibilities even on SaaS.

Microsoft runs Exchange and SharePoint. The customer still decides sharing policies, guest access, and whether that list should have been there. Data and access never leave the customer column.
