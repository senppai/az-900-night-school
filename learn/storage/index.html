📦Azure Storage services, tiers, and moving data

Blob, File, Queue, Table, and Disk; Hot / Cool / Cold / Archive; LRS through RA-GZRS; storage accounts; AzCopy, Storage Explorer, File Sync; Azure Migrate and Data Box.

💾“Azure Storage” is a family, not one box. The exam will describe a kind of data and expect you to name the service, the access tier, the redundancy, or the copy tool. Learn the family first; the rest is matching.

1. The storage services

Azure Blob Storage holds unstructured objects — photos, videos, backups, logs, data-lake files. Azure Files gives you managed file shares you can mount with SMB or NFS, like a cloud file server. Azure Queue Storage is a simple message queue between applications. Azure Table Storage is a NoSQL key-attribute store (cheap wide tables, not a relational database). Azure Disk Storage provides the managed disks that VMs boot from and attach as data disks. Blob/File/Queue/Table usually live in a storage account. Disks are their own resource, attached to VMs.

Pick the service that matches the data

Exam trap

Blob is objects, not a Windows drive letter. Files is the share you map as a network drive. Disk is what the VM believes is a local hard drive.

2. Storage accounts and types

A storage account is the unique namespace and settings box for blobs, files, queues, and tables (for example mystorageaccount.blob.core.windows.net). Standard general-purpose v2 is the account type Microsoft wants you to default to — it supports the current services, access tiers, and redundancy options. Premium accounts trade cost for performance: premium block blobs (low-latency objects), premium file shares, and premium page blobs (often for disks). Older account kinds (general-purpose v1, legacy Blob Storage accounts) may appear as “not the recommended default.”

Think

General-purpose v2 = the standard storage account for AZ-900. Premium = faster and more expensive for a specific workload.

3. Access tiers (Hot, Cool, Cold, Archive)

Blob access tiers trade storage price against access price. Hot: data you read and write often — highest storage price, lowest access price. Cool: infrequent access, typically kept at least 30 days. Cold: rarely accessed but still online with millisecond retrieval, typically kept at least 90 days — cheaper than Cool to store, more expensive to read. Archive: offline, cheapest to store, hours to rehydrate, typically 180 days minimum. Cold is an online tier. Archive is the offline one. That distinction is a favorite trap.

AZ-900 exam point

  • ★Hot / Cool / Cold / Archive are the current blob access tier names
  • ★Cold is online (fast retrieve); Archive is offline (hours)
  • ★Early retrieval can cost extra if you have not met the minimum days
  • ★Tiers are about how often you access blobs — not about LRS vs GRS

4. Redundancy options

Redundancy is how many copies Azure keeps, and where. LRS (locally redundant storage): three copies in one datacenter. ZRS (zone-redundant): copies across availability zones in the region. GRS (geo-redundant): LRS in the primary region plus async copies to the paired region. GZRS (geo-zone-redundant): ZRS in the primary plus copies to the secondary region. Add RA- in front (RA-GRS, RA-GZRS) and you get read access to the secondary region even before a failover — handy for read-heavy disaster-recovery designs. Conceptually: L = local building, Z = zones, G = another region, RA = you can read the other region.

Exam trap

GRS does not by itself let you read the secondary while the primary is healthy. That extra is the RA- (read-access) variants.

5. Moving files

AzCopy is a command-line tool built for high-throughput copies to and from Azure Storage (and between accounts). Azure Storage Explorer is the graphical app for browsing blobs, files, queues, and tables — same data, friendlier clicks. Azure File Sync sits on a Windows Server and syncs its files with an Azure Files share, with optional cloud tiering so old files live in Azure while the server keeps placeholders. File Sync is the “keep my on-prem file server, but back it with Azure Files” answer, not a one-shot copy.

  • • Scripts and big copies
  • • Fast, automatable
  • • No GUI required

  • • Click to upload, download, browse
  • • Great for people, not scheduled jobs

Ongoing sync

  • • Windows Server ↔ Azure Files
  • • Cloud tiering
  • • Not a bulk blob migration tool

6. Migration: Azure Migrate and Azure Data Box

Azure Migrate is the hub for discovering, assessing, and migrating workloads (servers, databases, web apps, and more) into Azure over the network. Azure Data Box is a family of physical devices Microsoft ships to you: you copy a large dataset onto the device, ship it back, and Microsoft uploads it into Azure. Use Data Box when the dataset is so large that copying over the WAN would take forever or cost too much. Migrate = plan and move systems. Data Box = truck the bits when the network is the bottleneck.

One sentence to remember

Pick Blob, Files, Queue, Table, or Disk for the data shape, a general-purpose v2 account unless you need premium, a Hot–Cool–Cold–Archive tier for how often you touch blobs, LRS/ZRS/GRS/GZRS (and RA- for reads on the secondary) for how many places keep copies, AzCopy or Storage Explorer or File Sync to move files, and Azure Migrate or Data Box when you are migrating whole workloads or too much data for the network.

Exam-style scene · Exam-style scene

A studio has 60 TB of finished videos they almost never watch, must keep for seven years, and their office internet cannot upload that much this quarter. They still want cheap storage once the data is in Azure.

Pick: Azure Data Box to ingest, then Blob Storage on the Archive (or Cold, if they need millisecond retrieve) tier.

Data Box solves the offline bulk transfer. Archive is the cheapest blob tier when hours of retrieval are acceptable. AzCopy over that internet would not finish in time; Azure Migrate is for workloads, not a pile of video files.
