AZ-900 quick sheet

Two ways to review. The quick sheet is for the night before; the detailed sheet is for spotting the traps. Print either one or save it as a PDF.

One line per concept, grouped by domain. About two printed pages.

Domain 01 · Cloud concepts · 25–30%

Cloud computing

  • Cloud computing — Renting compute, storage, networking over the internet, pay for use
  • CapEx vs OpEx — Buy up front (depreciates) vs pay as you go (cloud)
  • Consumption-based — No up-front cost; pay only for what you use; stop paying when you stop
  • Pay-as-you-go / Reserved / Spot — No commitment / 1–3 yr discount / cheapest but evictable
  • Serverless — No servers to manage; event-driven; billed per execution

Shared responsibility

  • Always Microsoft — Physical datacenter, network, hosts
  • Always customer — Data, devices, accounts and identities
  • Moves with the model — OS, network controls, apps: IaaS customer → PaaS shared → SaaS Microsoft

Cloud models

  • Public — Provider's shared hardware; no CapEx; fast scale
  • Private — One organization only; most control; you pay for hardware
  • Hybrid — On-premises + public cloud working together (Azure Arc manages both)
  • Multi-cloud — More than one public cloud provider

Benefits

  • High availability — Stay up when parts fail (zones, SLAs)
  • Scale up / scale out — Bigger instance (vertical) / more instances (horizontal)
  • Elasticity — Automatic scale out and in with demand
  • Reliability — Recover from failures and keep working
  • Predictability — Performance (steady speed) and cost (forecastable bill)
  • Security & governance — Platform security + policies applied everywhere
  • Manageability — Manage via portal, CLI, APIs, automation from anywhere
  • Sustainability — Efficient shared datacenters, renewable energy, less idle hardware

Service types

  • IaaS — VMs; most control; you manage OS and up; lift-and-shift
  • PaaS — App Service, SQL Database; you manage code and data
  • SaaS — Microsoft 365, Dynamics 365; you manage data, users, devices

Domain 02 · Azure architecture & services · 35–40%

Core architecture

  • Region — Datacenters in a geography with low-latency network
  • Availability zone — Separate datacenter(s) in a region; min 3 in zone regions
  • Region pair — Two regions for DR; staggered updates; prioritized recovery
  • Sovereign region — Isolated Azure: Azure Government (US), 21Vianet (China)
  • Hierarchy — Management groups → subscriptions → resource groups → resources
  • Subscription — Billing and access boundary
  • Resource group — Logical container, shared lifecycle; no nesting; one RG per resource
  • Management group — Organizes subscriptions; policy/RBAC inherit; 6 levels deep

Compute

  • Virtual machine — IaaS; needs size, OS disk, NIC on a VNet/subnet
  • VM Scale Sets — Identical VMs that autoscale
  • Availability set — Fault + update domains in one datacenter
  • Azure Virtual Desktop — Windows desktops and apps from the cloud
  • ACI / AKS / Container Apps — Simple container / orchestrated Kubernetes / serverless containers
  • Azure Functions — Serverless, event-driven code
  • App Service — PaaS for web apps and APIs
  • AI services / Machine Learning — Prebuilt AI APIs / train your own models
  • IoT Hub / IoT Edge — Manage devices in cloud / run workloads on devices

Networking

  • VNet / subnet — Private network in one region / address range inside it
  • VNet peering — Connect VNets over the Microsoft backbone (also across regions)
  • VPN Gateway — Encrypted over the internet (site-to-site, point-to-site)
  • ExpressRoute — Private connection, not over the internet
  • Azure DNS — Host DNS zones on Azure infrastructure
  • Private vs public endpoint — PaaS on a VNet private IP vs reachable from internet
  • NSG / Firewall / DDoS — Port rules / managed central firewall / flood protection

Storage

  • Blob / Files / Queue / Table / Disk — Objects / SMB-NFS shares / messages / NoSQL / VM disks
  • Hot / Cool / Cold / Archive — Frequent → rare; Archive is offline (hours to rehydrate)
  • LRS / ZRS — 3 copies in one datacenter / across zones
  • GRS / GZRS — LRS or ZRS + copy to secondary region; RA- = read secondary
  • Storage account — Globally unique name; Standard GPv2 is the default
  • AzCopy / Storage Explorer — Command-line copy / graphical browser
  • Azure File Sync — Windows Server ↔ Azure Files, with cloud tiering
  • Azure Migrate / Data Box — Assess and migrate workloads / ship data offline

Identity and security

  • Microsoft Entra ID — Cloud identity (formerly Azure AD): sign-in, SSO, MFA
  • Entra Domain Services — Managed domain join, LDAP, Kerberos — no DCs to run
  • SSO / MFA / Passwordless — One sign-in / 2+ factors / Hello, Authenticator, FIDO2
  • External identities — B2B guests with own credentials; customer sign-up
  • Conditional Access — If signal (location, device, risk) then MFA / block
  • Azure RBAC — Who can do what at which scope; least privilege
  • Owner / Contributor / Reader — All + grant access / manage, no access grant / view only
  • Zero Trust — Verify explicitly, least privilege, assume breach
  • Defense-in-depth — Layers: physical → identity → perimeter → network → compute → app → data
  • Key Vault / encryption — Store secrets, keys, certs / at rest (disk) vs in transit (TLS)
  • Defender for Cloud — Secure Score, recommendations, workload protection, multicloud

Domain 03 · Management & governance · 30–35%

Cost management

  • Cost factors — Resource type/size, region, usage, egress, purchase model
  • Pricing Calculator — Estimate before you deploy
  • Cost Management — Real spend, cost analysis, budgets, alerts
  • Tags — Name/value labels for cost and organization — not locks, not inherited
  • Reservations / savings plan — Commit to resource / commit to hourly compute spend
  • Spot / Hybrid Benefit — Evictable spare capacity / reuse your licenses

Governance and compliance

  • Microsoft Purview — Discover, classify, catalog, govern data
  • Azure Policy — Allowed configurations; Deny or Audit; initiatives group policies
  • Resource locks — CanNotDelete or ReadOnly; inherit; apply to Owners too
  • Service Trust Portal — Microsoft's audit reports (ISO, SOC) and compliance docs

Managing and deploying

  • Azure portal — Web GUI for everything
  • Cloud Shell — Browser shell: Bash or PowerShell with tools preinstalled
  • Azure CLI / PowerShell — az commands / Verb-Az cmdlets; same capabilities
  • Azure Arc — Manage on-premises and multicloud resources from Azure
  • Azure Resource Manager — The management layer every tool goes through
  • ARM templates / Bicep — Declarative JSON IaC / simpler language, same ARM deployment

Monitoring

  • Azure Advisor — Recommendations: reliability, security, performance, op. excellence, cost
  • Status / Service Health / Resource Health — Global public / your subscriptions / one resource
  • Azure Monitor — Collects metrics and logs from Azure, on-prem, other clouds
  • Log Analytics — Workspace to query logs with KQL
  • Alerts — Notify or act when a metric or log condition is met
  • Application Insights — APM for live apps: requests, failures, dependencies
